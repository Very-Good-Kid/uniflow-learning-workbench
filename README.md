# 高校智能学习工作台 · 界面层静态交互原型

为「高校智能学习工作台」（Vue 3 + Cordis + MySQL，见开发交接文档）配套做的界面层静态交互原型。不含真实后端，数据全部来自本地 mock，用来在写代码之前把页面结构、交互流程和状态细节定下来，开发照着实现即可。

同一套页面同时适配桌面 1440 与手机 390 两种视口，按 768px 断点切换，不是把桌面版缩小。

本仓库是对外发布的静态快照。纯静态、零构建、不依赖任何 CDN。

两种方式任选：

1. 直接双击任意 `*.html`，浏览器本地打开；
2. 或者起个本地服务，体验和线上一致：

```bash
python -m http.server 8080
# 访问 http://localhost:8080
```

## 页面清单

10 个页面，入口是 `index.html` 的交付清单。

| 文件 | 页面 | 说明 |
|---|---|---|
| `index.html` | 交付清单 | 全部页面入口，标注批次与对应交接文档章节 |
| `home.html` | 学习工作台（首页） | 桌面：三格概览 + 待办 / 日程左右两栏 + AI 入口，一屏不滚；手机：待办与日程装进同一个卡片，左右滑动切换，卡片内部各自滚动。管理员多一条「管理视角」概览 |
| `tasks.html` | 课程与任务 | 筛选默认收起（点「筛选」展开，6 个条件）、批量操作、任务表格、详情·编辑·新建抽屉，支持 `?id=`、`?new=1` 深链接 |
| `schedule.html` | 日程 | 七列周视图，真实钟点 7:00–23:00，冲突检测，点空白格新建，支持 `?date=` / `?event=` / `?course=` |
| `ai-plan.html` | AI 学习规划 | 左对话 + 右候选计划，文本为唯一入口，意图识别画成「已理解」条，确认后写回日程 |
| `library.html` | 学习资料库 | 列表 / 卡片流双视图，课程筛选卡带，详情抽屉，支持 `?q=` |
| `messages.html` | 消息与通知 | 顶栏铃铛对应的完整页面，含系统公告；标为已读后自动跳到下一条未读，未读清完时两栏一起收空 |
| `profile.html` | 个人中心 | 学籍卡（身份信息只读）；三个父入口：学习偏好、提醒设置、账号与安全；管理员在桌面多第四项「系统管理」，退出登录在最下 |
| `login.html` | 登录 | 桌面：校园照片打底 + 账号密码 / 扫码双页签；手机：只有账号密码，深绿渐变底。演示身份弹窗可切管理员、学生、停用账号 |
| `admin.html` | 系统管理 | 管理员后台，六个分支：用户管理、课程目录、资料管理、公告发布、系统配置、同步状态（只读）；左树默认收起，手机端为父子层级、表格横向滚动 |

全站共用侧边栏 6 项导航，管理员在底部多一条「系统管理」；顶部是搜索框与铃铛。「消息与通知」不占一级菜单，走顶栏铃铛。顶栏用户区点击直接进个人中心，没有下拉菜单。

顶栏还有一套全局搜索（Ctrl+K）：搜的是对象不是页面，按任务 → 资料 → 日程 → 课程 → 消息五类优先级命中，课程支持「高数 / 计网」等简称，↑↓ 选择、回车直达对应页面详情。列表页的过滤与搜索面板共用同一套匹配口径，避免面板条数和落地条数对不上。

## 移动端

按 768px 一档断点切换：≤768 走手机布局，769–1024 沿用桌面窄屏规则，不会回退成手机版。手机端不是把桌面缩小，而是按手机重排——宽表改卡片、双栏改上下、全宽抽屉加返回栏。

**导航**：底部五栏，全部直达、没有「更多」折叠，顺序为 **日程 / 任务 / 工作台 / 资料 / 我的**，工作台居中且默认选中。AI 规划走首页入口卡和顶栏图标，消息走顶栏铃铛。系统管理不占手机入口：管理员的个人中心里是一句「请在电脑端打开」，学生那句是权限说明。顶栏左侧只放页面名、不放品牌方块——那个绿块只是把标题往右推，手机上又没有别处需要它来确认「这是哪个应用」；标题与内容区左边缘对齐在 12px。

**日程**是手机端唯一做了结构改造的页面：外形借用紧凑周网格，**纵轴仍是真实的 7:00–23:00 钟点，不是课表节次**。这条务必按原型实现——照搬课表节次会把「一天里哪段时间空着」算错，Planner 排出来的学习时段就落不到真实时间上。手机固定 60px/小时、整块纵向滚动，日期栏与时间轴吸顶；默认工作日 5 列，可切全周 7 列，切换只改列宽，不横向滚动。

**弹窗与抽屉**：手机端所有全宽抽屉隐藏 TDesign 自带 header，改自绘返回栏——自带关闭按钮在满宽下会被推到屏外，用户点不回上一级。新建任务对话框高度封顶在视口内，头尾固定、内容区独立滚动，操作按钮吸在底部，滚动时窗口本身不动。

任务页的筛选抽屉顶部**不画拖拽把手**。底部有一条固定的「完成」栏，抽屉一旦能拖高，那栏的位置就跟着漂，用户会分不清它是「确认筛选」还是「收起抽屉」；画一条拖不动的假把手更糟，那是死控件。所以高度就按内容自然撑开、封顶 82vh，内容多的时候在抽屉内部滚，头和尾始终不动。

**短屏与工作台**：工作台在手机上是一个卡片盒子，待办任务和今日日程是盒内的两个子页，左右滑动切换，同一时间只露一页；卡片高度由内容区剩余空间决定，列表在卡片内部纵向滚，不再按屏幕高度另排一套上下布局。390×844 与 395×647 下整页都不滚。个人中心的主卡片同样只占剩余高度，资料在卡片内部滚，不会把整页撑长。

**页面标题只出现一次**：手机顶栏已经写着页面名（工作台 / 日程 / 学习资料库…），页内不再重复一个大标题。页头保留说明那行——里面有「22 份资料 · 7 门课程有资料」这类统计，也有「点空白格添加」这类操作提示——压成一行 11.5px 灰字，超出省略号。去掉的是重复，不是信息：日程页页头因此从 137px 降到 109px，多露半小时时间轴；资料库 97→67。工作台例外，它页内是「下午好，张三」，本来就不是标题。

**已知限制**：`admin.html` 只保证不溢出、能读，建议桌面使用；它的手机表格保持六列、在内容区横向滚动，不折成卡片（管理端字段太多，折卡片反而看不清一行是谁）。`index.html` 交付清单页未做手机适配；资料库顶部课程卡带在手机上靠手指横滑，桌面预览需按住拖动（已补指针拖拽）。

登录页两端形态不同：桌面保留校园照片 + 账号密码 / 扫码双页签；手机只有统一认证账号与密码，背景换成深绿渐变。两套 DOM 并列、按宽度显隐，登录校验共用一套逻辑，不存在「手机能登、桌面不能登」的分叉。

## 演示账号

进站有两条路，都不用记密码：

1. **点「使用演示账号进入」**：登录卡下方那个虚线按钮，点开列出三个身份，点一下直接进，账号密码都不用填。
2. **走登录表单**：账号填下表里的，**密码栏随便填**（`123456`、`abc` 都行），只要不为空——留给演示「密码为空被拦下」这个状态。真正校验的只有账号在不在名单里、是不是停用，密码本身不校验。

| 统一认证账号 | 身份 | 用来看什么 |
|---|---|---|
| `zhangsan` | 管理员 · 张三 | 侧边栏底部「系统管理」及六个管理分支 |
| `lisi` | 学生 · 李四 | 学生端全部页面 |
| `wangwu` | 已停用 · 王五 | 登录失败态 |

登录用的是统一身份认证下发的账号，**不是学号**。真实环境由学校认证中心校验密码，本平台不接收也不保存密码。已登录状态下再打开登录页会自动跳回首页。完整账号名单见 `assets/js/mock.js` 的 `users`。

换个人登录，顶栏的姓名和头像、首页问候语、个人中心身份卡都会跟着换；未登录直接双击打开某个页面时回退到演示账号张三，不会出现空白。退出登录会清掉会话并回到登录页。

**角色差异只在「能不能进系统管理」，但落到界面上的不是一条入口，而是内容本身。** 管理员登录后，工作台页头下面多一条「管理视角」：账号数、课程数、在架资料、生效公告、教务同步时间——这些数学生看不到，也不该看到。此外侧边栏底部有「系统管理」，个人中心设置区第四项也是它，点击进入管理端。

学生这三处都没有：工作台没有那条概览，侧栏底部直接不显示，个人中心只有三项并写一行说明；手敲 `admin.html` 会被挡回工作台并提示没有权限。其余页面两端完全一样——不为两种角色做两套界面。

**系统管理只在电脑端给入口。** 管理端只做到「不溢出、能读」，没按手机设计，所以在手机上：个人中心那一项换成一句「请在电脑端打开」的说明，「管理视角」条只显示数字、不带进入链接。管理端页面本身在手机宽度下仍能打开看，但不从界面引导，也不用它做验收。

顶栏不再挂角色标签：管理员看自己的名字和头像就知道是谁，标签只占位置、不传递信息。身份卡里的角色标签保留，因为那一块本来就在逐项列身份。

## 设计与实现约定

配色是学术绿体系，主色 `#006D5B`。全部令牌只在 `app.css` 的 `:root` 定义一次（`--brand-*` / `--warm*` / `--indigo*` / `--alert*`），并已接线 TDesign 主题变量。品牌名、学校名、导航、学期、演示账号只改 `config.js` 一处，禁止逐页替换。界面里显示的品牌是「高校智能学习平台」（暂定名，仓库名沿用项目名「工作台」），要改名只动 `brand.name` 这一行。

日程块的视觉只编码「这块能不能动」：课程是实心深绿底白字，来自教务、不可改；自己添加或 AI 已确认的是灰底，可改可删；待确认的是白底虚线，还没生效。类型差异只用块左侧 3px 色条暗示（学习时段靛蓝 / 个人日程琥珀 / 考试赭红），整块不再上色。学生最先要分清的是哪些不能动，不是有哪些类型。

工作台分两端排：桌面上页头、三格概览、AI 入口高度固定，待办任务和今日日程两张卡平分剩余高度并强制等高，任务或日程再多也只在卡片内部滚，整页不上下滑——日程通常比任务短，让卡片按内容高低会空出参差不齐的留白。手机上两张卡合并成一个盒子，待办与日程作为盒内两个子页左右滑动切换，同一时间只展示一页，卡片头部两个小圆点既标示当前位置，也可以点击切换；卡片高度吃满内容区剩余空间，列表在卡内纵向滚。个人中心的主卡片沿用同一口径：只占剩余高度，内容在卡内滚。

学习偏好是 Planner 的输入，不是一张要学生手画的日历。时段、周末策略、单次时长、每日上限、截止余量共同推导出可用时间池；偏好管「尽量」，例外（实习、家教）管「一定不行」。页面上有句「我这样理解你」把偏好翻译成人话，既是确认点，也是给开发看的数据结构；改动会立刻算出对已确认学习时段的影响，不会悄悄让旧安排落空。

筛选只在**条件多的页面**才折叠：课程与任务有来源 / 状态 / 课程 / 类型 / 到期加排序共 6 个，收进第二行、点「筛选」展开，按钮上带生效条数，否则不知道「筛过」还是「全量」。资料库只有分类和排序两个、系统管理的用户管理只有角色和状态两个、资料管理只有一个状态——这三个直接摊在工具条里，收起只省 40px 却要多点一次，不划算。消息页的状态与来源是 chip 形态，本来只占一行。

系统管理左侧的分类树同样默认收起：用户管理只列到学院一级、资料管理只列到课程一级，点箭头才展开专业 / 类别。展开的树会把 6 个学院摊成十几行，右表反而只剩半屏。收起时如果正选着某个专业，选中态收回到所属学院，否则被选中的行消失、表格却还按它筛着。手机上这条树是横向 chip，折叠箭头不显示，点学院胶囊会一并展开。

滚动条默认隐形，滚动时才出现，停手 800ms 淡出。宽度固定 8px，轨道一直占位，所以出现时不会把内容挤动。实现分两半：样式在 `app.css` 末尾（`*::-webkit-scrollbar-thumb` 透明，`.is-scrolling` 时上色），触发在 `shell.js`——scroll 事件不冒泡，只能挂在捕获阶段监听，给真正在滚的那个元素挂 `.is-scrolling`。横向卡带（资料库课程条）同理。

个人中心的学籍字段（姓名、学号、学院、专业、年级）只读，由教务同步，不开放修改；能改的只有头像和昵称，昵称只用于称呼，不替代真名。登录、改密码、找回密码、注销都不在本平台，账号归学校统一身份认证。

`mock.js` 的字段名与 `backend/src/models/index.ts` 保持一致，接接口时不需要二次映射。演示态用 sessionStorage 持久化：任务走 `Store`、日程走 `EventStore`、消息走 `NotifyStore`、管理端数据走 `AdminStore`，同标签页内跨页面共享，关掉标签页复位。改日程必须通过 `commit()` 写回，直接改 `MOCK` 原数组不会触发界面更新。

学期演示口径是 2026–2027 学年第一学期第 12 周（11/16–11/22），「今天」为 11/18 周三。页面里所有统计数字由 mock 实时计算，没有写死。周末保留：课表默认显示周末列，可用时间可含周末，规划器也允许把学习时段排到周末。

AI 规划页的文本是唯一输入入口，按钮和抽屉只负责把结构化选择翻译成一句话塞进输入框，统一走同一个 `send()`；排学习时段前会先扣掉该任务已排过的时长，避免同一项被排两遍。系统管理里发布的公告会直接写入消息中心的「系统公告」来源，顶栏未读角标同步变化，可以去消息页验证。
